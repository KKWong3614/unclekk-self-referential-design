# 改进策略（元层 · 可编辑）

本文件规定：发现问题之后**如何改进**这个 Agent。它本身也在可演化清单内——
这就是「元认知自修改」：不只改行为，还改产生改进的机制。

## 改进流程

1. 每轮任务结束，记录 `utility`（0~1 任务达成度）与 `violations`（违规次数）。
2. **归因**：判断问题出在提示词、工具、记忆，还是**归因方式本身错了**。
3. **提议**：生成一条具体修改，只进隔离区，不直接生效。
4. 过闸后进入试用期；累计若干轮再裁决，变差则**回滚**。
5. 被拒与**回滚**的改动连同原因存入 `ledger/archive.json` 作为负样本。

## 何时应该改我自己

- 连续 3 次裁决全部回滚 → 问题不在规则，而在「找规则的方式」，此时才改本文件。
- 改动本文件前必须取得**人类确认**（见 CONTRACT.md）。
